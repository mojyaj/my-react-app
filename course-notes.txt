Style React Components with CSS

3 CSS Styling methods
1) External CSS
2) Modules CSS  *Purposed for React Components
3) Inline CSS

1. External
    - Easy for simple projects
    - Flexibility with Media Queries & Psuedo Selectors
        - @media only screen and (max-width: 600px) { ... }
        - .button:focus
    - 'index.css'
    - Can lead to naming conflicts while working with many components/Modules
2. Modules
    - Dedicated Style Sheet for each component
    - Scoped
    - React Modules naming convention
        - 'component.module.css'
    - Styles are applied to components via the 'className' attribute
        - example, <button className="styles"> </button>
    - Avoids Naming Conflicts
        - Each className is unique
        - Generated class name via hashing algorithm
    - Each Component has their very own styles
    - Lacks global CSS setup like normal external CSS files
    - GLOBAL CSS + CSS Modules
        - import at top level in 'main.jsx'
        - 'globals.css' or 'index.css'
        - shared utility classes (.container, .btn)
3. Inline
    - Create an object to store styles
    - Great for components with minimal styling
    - Convenient
        - No classes/ids
        - No Naming Conflicts with global styles
    - Downsides
        - Less maintainable in larget applications
        - Not great for complex styling
        - Reduces readability of components

Props
    Read-Only (immutable) properties that are shared between componnents.
    A parent componenet can send data to a child component.
    <Component key=value />

    'Props' are arguments passed into React components via HTML attributes
     Example, 
        Component:
        <Student name="Spongebob" age={30}  isStudent={false}> </Student>
                 ^^^^             ^^^       ^^^^^^^^^

        *Values that are type String should be encased in double-quotes ("").

PropTypes
    Validate props at runtime in React apps
    A mechanism that ensures that the passed value is of the correct datatype.
    Only adds WARNINGS in development so you catch bugs early.
    Only works in Development. No effect in production.
    Modern React developers use TypeScript, NOT prop-types.
    npm install prop-types
    Module,
        import PropTypes from 'prop-types'
    Example,
        Declare the 'propTypes' of the 'prop' called, 'Student'
            Student.propTypes = {
                name: PropTypes.string,
                age: PropTypes.number,
                isStudent: PropTypes.bool
            }
        ** See Default Props section below
            it creates a prop differently

    Common PropTypes
        User.propTypes = {
            name: PropTypes.string.isRequired, // This prop is REQUIRED
            age: PropTypes.number,
            isAdmin: PropTypes.bool,
            hobbies: PropTypes.array,
            user: PropTypes.object,
            onClick: PropTypes.func,
        };     

    Default Props
        Default values for props in case they are not passed from the parent component
        defaultProps does not reliably work with modern function components anymore in React.
            Officially removed in React 19
        defaultProps DO WORK for class components
        *TypeScript is still prefered over defaultProps
        Default values only apply when the prop is "undefined" NOT when its "null"
    Example,
        Component.defaultProps = {
            name: "John",
            age: 0,
        }

ES6/JavaScript Default Parameters

useState() Hook

React Hook
    Special function that allows functional components to use React features
    without writing class components (Reactv16.8).
    React Hook functions let you “hook into” React features inside function components.

useState()
    A React hook that allows the creation of a stateful variable AND a setter
    function to update its value in the Virtual DOM.
    [name, setName] = useState()
    - Adds state (memory) to a component

React Hook Module
    - import React, { useState } from 'react'
    - 'React' is default export
    - useState, useEffect, useContext, useReducer, useCallback, and more
    - Encase stateful a variable and its setter function inside square 
        brackets [] (Array descructoring)
    - state can be anything - number, string, boolean, array, object
    - Never modify stateful 'variables' directly
        - Only use the 'setter'
    - Never manipulate the DOM directly in React components
        - Use React Hooks to manipulate the DOM instead
    - Only call hooks at the top level
    - Only call hooks inside React functions
    - State updates are asynchronous
        Calling this sequentially does not work:
            setCount(count + 1)
        but calling this sequentially works:
            setCount(prev => prev + 1)

React Updater Functions

Updater Function
    A function passed as an argument to setState() or other React functions
    example, 
        setYear( c => c + 1 );
        setState( Arrow Function OR Updater Function );
    Allow for safe updates based on the previous state 
    Used with multiple state updates and asynchronous functions
    Good practice to use updater functions

How does a Prop get updated when calling multiple setState()?
    1) Uses the CURRENT state to claculate the NEXT state
    2) set functions do not trigger an update
    3) React batches together state updates for performance reasons
    4) NEXT state becomes the  CURRENT  state after an update
    - Other Notes
        - Takes the PENDING state to calculate NEXT state
        - React puts your updater function in a queue (First-In First-Out)
        - During the next render,  it will call them in the same order

Update OBJECT state

*Refer to related 'src-update-OBJECTS' folder in 'old-files' folder
    'MyComponent.jsx'

To update a JavaScript Object, you must use the 'spread operator' and then assign 
    the property that needs to be updated
    example, 
        setCar({...car, year: 2025});
    The above example is similar to
        setCar({year: 2024, make: "Ford", model: "Mustang", year: 2025});
    *The final JavaScript Object will have 'year' equals '2025' because 
        if there are duplicate property assignments, then JavaScript will use 
        the latter.
    JavaScript does not allow Objects to have duplicate keys
    'setCar()' should utilize updater function as this is best practice
    example,
        setCar( car => ({...car, year: event.target.value}) );
                       ^                                  ^
        *Surround the arrow function with paranthesis because JavaScript will
          think that we are trying to create multi-lined code.

React useEffect React Hook

useEffect() = React Hook that tells React DO SOME CODE WHEN,
                 (pick on):
                        - This component re-renders
                            - also on INITIAL render of the page
                        - This component mounts
                        - The state of a value

useeffect(func, [dependencies])   // When any 'dependencies' change, invoke 'func'

Context:
    ** Mount - Adding react component to DOM
    ** Un-Mounting- Removing react component from the DOM

1) useEffect( () => {})             ** Run on every render
                                        *Usually avoided.
2) useEffect( () => {}, [])         ** Runs once only on mount
                                        *Runs once when component appears
                                        
3) useEffect( () => {}, [value])    ** Runs once mount AND 
                                    ** Runs again whenever 'value' changes
Use Cases:
    1) Event Listeners
    2) DOM Manipulation
    3) Subscriptions (real-time updates)
    4) Fetching Data from an Applications
    5) Clean up when a component unmounts

Clarity on 'useEffect()' and Uses

React Component Behavior
    Any code directly inside the component body will execute multiple 
    times because React Components re-render multiple times.
        - on initial render
        - every state update
            - React re-runs the ENTIRE component function
        - every re-render

    Event listeners belong inside useEffect()
    
    Never put side effects directly in the component body
        such as,
            - event Listeners
            - timers
            - API calls
            - DOM manipulation
    
    React components should mainly:
        - calculate UI
        - return JSX

    If the component disappears:
        - listener still exists
        - duplicates can accumulate
        - memory leaks happen
        - weird bugs happen

useContext() Hook

useContext() - React Hook that allows you to share values between multiple
                levels of components without passing props through each level.

Provider Component
    1) import {createContext} from 'react';
    2) create & export context: 
            export const UserContext = createContext()
    3) <MyContext.Provider value={value}>
            <Child />
        </MyContext.Provider>
    *see 'ComponentA.jsx'

CONSUMER COMPONENTS:
    1) import { useContext } from 'react'
    2) consume context:
            const value = useContext(MyContext);
    *see 'ComponentC.jsx' or 'ComponentD.jsx'

Talking Points
    - Props Drilling
        - When data (props) is passed down through multiple layers of 
            components to reach a deeply nested child that actually needs it.
        - ISSUE: passing 'props' down to each child components can be very tedious
            - anti-pattern
            - difficult to maintain
            - triggers many unnecessary re-renders
            - reduced reusability
            - tightly coupled
        - Solution: useContext() hook
            - share values between multiple levels of components
            - allows a deeply nested child to access variables from higher
                in the Component Hierarchy
